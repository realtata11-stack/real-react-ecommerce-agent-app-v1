# Client Brief: เว็บหน้าร้าน My Store

- **จาก:** เจ้าของร้าน My Store
- **ถึง:** ทีมพัฒนา
- **ไฟล์แนบ:** [design-notes.md](./design-notes.md), โฟลเดอร์ [screenshots/](./screenshots/), รูปแบนเนอร์และโปรโมชันใน `public/images/`

## 1. เราอยากได้อะไร

My Store เป็นร้านขายของออนไลน์ที่มีสินค้าหลายหมวด ตั้งแต่เครื่องสำอางไปจนถึงของใช้ในบ้าน ตอนนี้เรายังไม่มีเว็บหน้าร้านของตัวเอง

เราอยากได้เว็บที่ลูกค้าเข้ามาดูสินค้า หยิบใส่ตะกร้า กรอกที่อยู่จัดส่ง แล้วกดสั่งซื้อได้ครบในที่เดียว

ทีมออกแบบทำภาพหน้าจอไว้ให้แล้วทุกหน้า ขอให้หน้าตาออกมาตามภาพ ส่วนโค้ดข้างในจะจัดอย่างไร ทีมพัฒนาตัดสินใจได้เอง

เรายังไม่มีระบบหลังบ้าน รอบนี้ให้ใช้ข้อมูลสินค้าจาก DummyJSON ไปก่อน อีกไม่กี่สัปดาห์เราจะมี API ของร้านเอง แล้วจะสลับมาใช้ตัวนั้น

## 2. ลูกค้าของเราทำอะไรได้บ้าง

ทุกหน้ามีส่วนหัวและส่วนท้ายเหมือนกัน

- **ส่วนหัว:** ชื่อร้าน เมนู Home และ Products และไอคอนตะกร้าที่มีตัวเลขบอกจำนวนสินค้าในตะกร้า
- **ส่วนท้าย:** ข้อมูลติดต่อร้าน รายชื่อหมวดสินค้าแนะนำ และลิงก์ไปหน้าหลักของเว็บ

### หน้าแรก

- เห็นแบนเนอร์ใหญ่ที่เลื่อนเองได้ และกดเลื่อนเองได้
- เห็นจุดเด่นของร้าน 4 ข้อ
- เห็นสินค้า "Deals of the day" 5 ชิ้น พร้อมนาฬิกานับถอยหลัง
- เห็นภาพโปรโมชัน 4 ภาพ
- เลือกหมวดสินค้าจากรายการด้านข้าง แล้วเห็นสินค้าตัวอย่างของหมวดนั้นทันที
- กดสินค้าชิ้นไหนก็ได้เพื่อไปดูรายละเอียด

### หน้ารายการสินค้า

- เห็นหมวดสินค้าทั้งหมด และรู้ว่ากำลังดูหมวดไหนอยู่
- เห็นสินค้าของหมวดที่เลือก หน้าละ 20 ชิ้น
- เปลี่ยนหน้าได้เมื่อสินค้ามีมากกว่าหนึ่งหน้า

### หน้ารายละเอียดสินค้า

- เห็นรูปสินค้า และเลือกดูรูปอื่นได้เมื่อสินค้ามีหลายรูป
- เห็นชื่อ ยี่ห้อ คะแนน ราคา ราคาก่อนลด ส่วนลด และคำอธิบาย
- เห็นข้อมูลสต็อก การจัดส่ง และการรับประกัน
- เห็นรีวิวของลูกค้าคนอื่น พร้อมสรุปว่ามีคนให้กี่ดาวกี่คน
- กด "Add To Cart" เพื่อหยิบใส่ตะกร้า แล้วได้รับการยืนยันว่าใส่ตะกร้าแล้ว

### หน้าตะกร้า

- เห็นสินค้าทุกชิ้นที่หยิบไว้ ราคา จำนวน และยอดรวมของแต่ละรายการ
- เห็นว่าประหยัดไปเท่าไรจากราคาก่อนลด
- เพิ่มหรือลดจำนวน และลบสินค้าออกได้
- เห็นยอดรวมทั้งหมด และกดไปหน้า Checkout ได้
- ถ้าตะกร้าว่าง เห็นข้อความบอกว่ายังไม่มีสินค้า

### หน้า Checkout

- กรอกที่อยู่จัดส่ง อีเมล และเบอร์โทร ถ้ากรอกไม่ครบหรืออีเมลผิดรูปแบบ เห็นข้อความบอกว่าผิดตรงไหน
- เลือกวิธีจัดส่ง ค่าส่งและยอดรวมเปลี่ยนตามวิธีที่เลือก
- เลือกวิธีชำระเงิน
- เห็นสรุปรายการสินค้าและยอดที่ต้องจ่าย
- กด "Place Order" ได้เมื่อบันทึกที่อยู่แล้วเท่านั้น

### หน้าสั่งซื้อสำเร็จ

- หลังกดสั่งซื้อสำเร็จ เห็นหน้ายืนยัน และตะกร้ากลับมาว่าง

## 3. สิ่งที่ต้องถูกต้อง

เรื่องเหล่านี้ลูกค้าของเราจะสังเกตเห็น ถ้าผิดถือว่างานยังไม่เสร็จ

1. **ดาวต้องตรงกับคะแนน** คะแนนสินค้าเต็ม 5 สินค้าที่ได้ 4.96 ต้องเห็น 5 ดาว ไม่ใช่ 2 ดาว
2. **ส่วนลดเป็นจำนวนเต็ม** แสดง "10% Off" ไม่ใช่ "10.48% Off"
3. **ราคาที่ได้จากระบบเป็นราคาหลังลดแล้ว** ราคาก่อนลดให้แสดงแบบขีดฆ่า
4. **เงินแสดงเป็นดอลลาร์ ทศนิยมสองตำแหน่งเสมอ** เช่น `$9.99`
5. **ตะกร้าต้องไม่หาย** ปิดแท็บหรือรีเฟรชแล้วกลับมา ของในตะกร้ายังอยู่
6. **เปิดได้ทุกหน้าจากลิงก์ตรง** ลูกค้าคัดลอกลิงก์หน้าสินค้าไปส่งให้เพื่อน เพื่อนต้องเปิดได้ และกดรีเฟรชหน้าไหนก็ต้องไม่พัง
7. **ทุกจุดที่รอข้อมูลต้องบอกลูกค้า** ระหว่างโหลดต้องเห็นว่ากำลังโหลด ถ้าโหลดไม่สำเร็จต้องเห็นข้อความ ห้ามปล่อยให้หน้าว่างเปล่า
8. **หน้าสั่งซื้อสำเร็จต้องเห็นได้หลังสั่งซื้อจริงเท่านั้น**
9. **ถ้าสั่งซื้อไม่สำเร็จ ลูกค้าต้องรู้** และของในตะกร้าต้องยังอยู่
10. **ลิงก์ทุกอันในส่วนหัวและส่วนท้ายต้องกดได้จริง**
11. **ชื่อแท็บของเบราว์เซอร์เป็นชื่อร้าน** ไม่ใช่ชื่อเครื่องมือที่ใช้สร้าง

## 4. สิ่งที่ยังไม่ทำในรอบนี้

- ระบบสมาชิก เข้าสู่ระบบ และประวัติการสั่งซื้อ
- การค้นหา การเรียงลำดับ และตัวกรองราคาหรือคะแนน
- การชำระเงินจริง
- หน้าจอมือถือและแท็บเล็ต รอบนี้ขอให้ใช้งานได้ดีบนจอคอมพิวเตอร์กว้าง 1200px ขึ้นไป
- หลายภาษา ข้อความบนเว็บเป็นภาษาอังกฤษทั้งหมด
- โหมดมืด

## 5. ข้อกำหนดจากทีมเทคนิคของร้าน

ทีมเทคนิคของเรากำหนดไว้เท่านี้ นอกเหนือจากนี้ทีมพัฒนาเลือกได้เอง

- ใช้โปรเจกต์เริ่มต้นที่ให้ไว้: React 19, TypeScript และ Vite
- จัดหน้าตาด้วย Tailwind CSS v4
- ดึงข้อมูลจาก API ผ่าน TanStack Query
- ที่อยู่ของ API ต้องอ่านจากตัวแปร `VITE_API_BASE_URL` ในไฟล์ `.env` ห้ามเขียนที่อยู่ลงในโค้ดตรง ๆ เพราะเราจะสลับไปใช้ API ของร้านเองในภายหลัง
- งานทุกชิ้นต้องผ่านคำสั่ง `npm run check`
- เว็บต้องนำขึ้น Vercel ได้

## 6. ข้อมูลและ API

ข้อมูลทั้งหมดมาจาก [DummyJSON](https://dummyjson.com/docs/products) รอบนี้ใช้เท่านี้

| ใช้ทำอะไร | คำขอ |
| --- | --- |
| รายการสินค้า | `GET /products?limit=&skip=` |
| รายชื่อหมวด | `GET /products/categories` |
| สินค้าในหมวด | `GET /products/category/{slug}?limit=&skip=` |
| รายละเอียดสินค้า | `GET /products/{id}` |
| ส่งคำสั่งซื้อ | `POST /carts/add` |

DummyJSON ไม่ได้บันทึกคำสั่งซื้อจริง แต่ตอบกลับเหมือนบันทึกแล้ว ซึ่งพอสำหรับรอบนี้

รูปร่างของคำสั่งซื้อที่ส่งไปต้องเป็นแบบนี้ เพราะ API ของร้านที่จะมาแทนจะรับรูปร่างเดียวกัน

```json
{
  "userId": 1,
  "products": [{ "id": 1, "quantity": 2 }],
  "address": {
    "address": "99 Sukhumvit Road, Bangkok 10110",
    "email": "customer@example.com",
    "phone": "0812345678"
  }
}
```

## 7. วิธีตรวจรับงาน

เราจะเปิดเว็บที่ขึ้น Vercel แล้ว และลองทำตามนี้ทีละข้อ

1. เปิดหน้าแรก เห็นทุกส่วนตามภาพ แบนเนอร์เลื่อนเอง นาฬิกานับถอยหลังเดิน
2. เลือกหมวดในหน้าแรก สินค้าเปลี่ยนตามหมวด
3. เข้าหน้ารายการสินค้า เลือกหมวด Groceries แล้วไปหน้า 2 ได้
4. กดสินค้าหนึ่งชิ้น เห็นรายละเอียดและรีวิวครบ ดาวตรงกับคะแนน
5. กด Add To Cart เห็นการยืนยัน ตัวเลขที่ไอคอนตะกร้าเพิ่มขึ้น
6. เข้าหน้าตะกร้า เพิ่มจำนวน ลดจำนวน ลบสินค้า ยอดรวมถูกทุกครั้ง
7. รีเฟรชหน้าตะกร้า ของยังอยู่
8. เข้าหน้า Checkout กด Submit ทั้งที่ยังไม่กรอก เห็นข้อความเตือนครบทุกช่อง
9. กรอกที่อยู่ให้ถูก บันทึก เปลี่ยนวิธีจัดส่ง ยอดรวมเปลี่ยนตาม
10. กด Place Order ไปถึงหน้าสั่งซื้อสำเร็จ ตะกร้าว่าง
11. คัดลอกลิงก์หน้าสินค้าไปเปิดในแท็บใหม่ เปิดได้
12. เปิดหน้าแรกค้างไว้ ปิดอินเทอร์เน็ต แล้วกดไปหน้ารายการสินค้า เห็นข้อความแจ้งว่าโหลดไม่สำเร็จ
